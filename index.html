01
IT support platform React · FastAPI · SQLAlchemy

SupportOps Diagnostic Portal

A React/FastAPI support workspace for public-target diagnostics, troubleshooting notes, and tickets. The most important work in this project is the network boundary and failure handling, not the dashboard itself.

Problem

A hostname could pass validation, then resolve differently when the network tool used it. That left a DNS-rebinding gap in a service that makes outbound connections for users.

Decision

Validate again at the execution boundary, reject mixed public/private answers, pin the approved public IP, and keep the same request reference through the result and ticket.

Verification

Regression tests cover rebinding, timeout, capacity saturation, database persistence failure, and bounded output. A separate dated live check records the deployed example.com diagnostic and the dashboard availability observed during that run.

Limit: the regression tests verify application behavior for these failure paths; they are not production-scale load testing.

IT support engineering project PowerShell · Python · GitHub Actions

Enterprise IT Support Lab

A Windows troubleshooting project with endpoint checks, PowerShell remediation, and documented DNS, service-state, and disk-pressure cases.

Problem

While extending the toolkit, I found that a healthy collector run was not enough to explain how I would handle DNS failure, a stopped service, or disk pressure.

Decision

I documented the three troubleshooting cases with competing hypotheses, before/after evidence, preview-first changes, retests, and escalation notes.

Verification

The WARN → PASS transitions are automated regression/case-harness results using the same collector logic. Separately, the Windows Server 2025 verification checks the live environment and records its own health output.

Limit: no customer or employer data is included, and the project does not claim production fleet ownership.

03
Subscription application Next.js · TypeScript · PostgreSQL

SaaS Foundation

A Next.js subscription application with credentials auth, user-owned data, Stripe billing, rate limits, and a billing recovery path for duplicate or out-of-order webhook delivery.

Problem

While working through the auth flow, I found that an existing passwordless account could gain a password without a verification step. Later, the Stripe webhook also needed duplicate-event and ordering protection.

Decision

Make credential transitions explicit, process Stripe events idempotently, reject stale or superseded subscription events, and add dry-run reconciliation before repair.

Verification

Auth and billing policy tests cover the failure cases; CI also runs dependency audit, lint, Prisma validation, tests, and a production build.

Limit: CI does not contain Stripe credentials, so policy tests are not described as end-to-end Stripe test-mode webhook delivery.

04
Launch mechanics prototype Next.js · TypeScript · Meteora DBC concepts

CurveClarity

A launch-design prototype for making token launch assumptions and buyer disclosures easier to inspect before a launch. Builders can compare illustrative curve profiles, adjust scenario inputs, review disclosure checks, and export a draft brief.

Problem

Launch mechanics, fee assumptions, liquidity destinations, and token unlock details can be difficult to understand when they are scattered across separate tools and documents.

Decision

Put curve previews, editable assumptions, graduated liquidity allocation, and plain-language allocation and unlock disclosures into one review flow.

Current state

The source includes three illustrative curve profiles, responsive controls, disclosure readiness checks, and a JSON launch brief export. Values are labeled as assumptions.

Prototype limit: curve previews are presentation-only; no Meteora SDK quote simulation, wallet connection, on-chain transaction, or live demo is included yet. Verify all settings with the official DBC SDK before deployment.
